# Manual Verification Checklist

Use only the checks applicable to the declared scope and record the environment and evidence.

- [ ] Keyboard reachability, activation, focus visibility, order, placement, and escape
- [ ] Screen-reader names, roles, values, states, errors, instructions, and announcements
- [ ] Reading order and landmark/heading navigation
- [ ] 200% zoom, 400% reflow where applicable, viewport/orientation states
- [ ] Contrast across default, hover, focus, active, disabled, and high-contrast states
- [ ] Color-not-alone and visual-meaning alternatives
- [ ] Reduced motion, animation control, flashing, and media alternatives
- [ ] Alt-text, caption, transcript, label, instruction, and error-message purpose
- [ ] Cognitive clarity, predictability, recovery, sensory load, and avoidable effort
- [ ] Localization expansion and translated meaning
- [ ] PDF tags, language, headings, reading order, lists, tables, links, and forms
- [ ] Documented design intent compared with implemented behavior
- [ ] Representative disabled-user research/testing when required by risk and scope

Do not check an item merely because it was unavailable. Leave it open. Pending checks block `VERIFIED PASS`; they do not erase an independently established `VERIFIED FAIL` supported by reproducible normative evidence.
