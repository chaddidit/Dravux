# Input Capabilities

Choose the matching input class before running checks. For every class, document the exact tools used and preserve errors.

| Input | Automated checks | Required manual checks | Unsupported/limited | Required evidence | Error conditions |
|---|---|---|---|---|---|
| Live/local website | DOM/HTML rules, selected computed styles, document metadata, link/form/image presence, scanner output when available | Keyboard, focus sequence, screen reader, zoom/reflow, responsive/device states, motion, media, task completion | Authentication and dynamic states unless access is explicitly available; automation cannot establish full conformance | URL, viewport, state, timestamp, tool/version, selector/DOM excerpt, screenshot when helpful | Unreachable target, blocked auth, tool crash, incomplete render, unsupported browser state |
| HTML/CSS/JS/TS/JSX/TSX | Static patterns, semantics, attributes, token values, deterministic tests, existing lint/scanner output | Runtime behavior, accessible names after render, focus, AT announcements, device/input modes | Generated/runtime semantics may differ from source; do not execute untrusted code by default | File/line, exact excerpt, build/runtime context, reproduction command | Parse/build failure, missing dependency, framework transform unavailable |
| Markdown/structured content | Heading/link/image metadata, required fields, schema/JSON structure, plain-language heuristics | Meaning, hierarchy quality, link purpose, alt-text purpose, cognitive clarity | Heuristics are advisory unless a normative requirement applies to rendered output | File/line or JSON pointer, rendered context when available | Malformed input, missing schema/context, unsupported encoding |
| SVG/image metadata | SVG parse, title/description/role/contrast values where deterministic, metadata presence | Image purpose, text alternative quality, visual meaning, complex diagram equivalence | Raster pixels alone do not reveal purpose; OCR is not semantics | File, element/attribute, rendered preview, use context | Corrupt file, unsupported format, missing use context |
| PDF | Metadata/text extraction, tagged-structure inspection when a capable tool exists, visual rendering | Tags/reading order, document language, headings, links, tables, forms, zoom/reflow, AT behavior | Visual rendering alone cannot prove semantic accessibility; OCR text is not reading order | File hash/name, page, extractor/renderer, structural output, screenshot | Encrypted/corrupt PDF, missing semantic tool, extraction failure |
| Screenshot/visual evidence | Dimensions, color sampling/contrast calculation, OCR as advisory | Meaning, state, interaction, reading order, content purpose, full-screen context | Cannot prove DOM, programmatic names, focus, keyboard, or AT support | Image file, crop/full context, state description, calculation inputs | Missing state/context, ambiguous pixels, compression/color-profile uncertainty |
| GitHub artifact | Patch/source inspection, issue/PR/report schema, workflow syntax, scanner-result import | Runtime behavior, manual accessibility tests, code-review judgment, merge/release approval | Do not mutate repositories or use tokens without explicit approval | Repo/ref/commit or local path, file/line, workflow/run source, report attachment | Missing checkout/artifact, permissions, stale ref, malformed scanner output |
| Unsupported input | No fabricated check | Decide whether an export or alternate evidence source is acceptable | Binary/proprietary formats without a reader; inaccessible remote/session state | Input description and attempted capability check | Return automated `ERROR`; final `NOT APPLICABLE` only if genuinely out of declared scope, otherwise `INCOMPLETE` |

## Capability decision

If only part of an input can be evaluated, run `dravux_run.py preflight` before acquisition. A lower selected mode requires explicit user acknowledgement. Never silently narrow the scope or treat an unavailable check as passed.

## Source-only live mode

For a public unauthenticated URL without confirmed browser/scanner tooling, declare `SOURCE_TEXT` or `RAW_SOURCE` as the available mode and ask the user to accept it before retrieval. After acceptance, make one passive retrieval of the exact named page. Record the requested URL, redirect chain, final URL, response status, timestamp, retrieval tool/version, and content hash when available. Do not crawl links, authenticate, submit forms, activate controls, download unrelated assets, or mutate remote state.

`SOURCE_TEXT` permits only retrieved-text observations and potential advisory hypotheses. It cannot establish HTML attributes, functioning landmarks, accessible names, DOM relationships, computed styles, contrast, keyboard behavior, assistive-technology output, responsive states, motion, or client-side state. A successful accepted lower-mode acquisition is not an automation `ERROR` merely because those higher-mode capabilities are absent; keep them excluded and end `INCOMPLETE`. Use `ERROR | INCOMPLETE` when acquisition or selected-mode execution fails.
